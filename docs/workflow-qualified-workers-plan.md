# Qualified workers and automatic assignment

## Approved direction and current stage

The user approved one qualified worker per unassigned Job, preserving existing assignments, selecting an available worker, preferred order to resolve ties and a scheduling-contact notice when nobody can be booked. November 21: the user approved the canonical UI. Qualification persistence, workflow authoring/editing and atomic worker selection/booking are connected locally. The former UI checkpoint notes below record the staged design; the connected behavior and verification at the end supersede their former not-live status. Existing workflows are not upgraded automatically.

## Selection policy for connection

Use stable workspace service IDs. Store an explicitly ordered, unique list of qualified active people per service. The first slice chooses one person; it does not infer skills, team size, round robin, location, multi-day work, licenses or external availability.

For a future newly created matching unscheduled Job with no primary owner and no additional assigned people, compare all eligible workers' complete available intervals. Choose the earliest valid start; use the saved preferred order only when starts tie, with stable identity as the final deterministic fallback. A higher-priority worker who is available later must not displace an earlier valid slot. Respect current service qualifications, working hours, full-day exceptions, complete Calendar occupancy, unknown work duration, configured duration/gap, deadlines, saved timezone and the original occurrence cutoff.

Qualifications govern people chosen by the system. If a Job already has explicit assignments, preserve them and use the established assigned-people booking path; do not replace manual assignments or infer that a manual assignee is qualified. The review says Choose a qualified worker **if unassigned**. An existing linked/shared visit requiring crew coordination must not receive an inferred assignment; leave it unchanged and request manual assignment through the normal no-slot notice when that bounded case is unsupported.

If no qualified worker has a valid slot, leave both assignment and schedule unchanged and send one actionable notice to the selected contact through the chosen channels. Never persist a tentative worker merely to search. Success must save assignment, canonical planned visit, receipt/history and notification intents atomically. Existing bookings are never moved to create a slot.

Editing assignment policy follows the established future-only Edit lifecycle; qualification saves do not enroll old Jobs or directly assign/book work.

Do not call the existing booking search once per candidate with repeated database/authentication reads. Reuse its interval selector and authoritative canonical scheduling boundary. 4. Qualified selection additionally requires current full-workspace Job assignment authority; the existing assigned-people mode retains its current permissions. ## Connected implementation — November 21

Migration `202611210003_service-qualified-workers.ts` adds ordered workspace/service/person references, membership/service foreign keys and bounded preferred positions. Existing settings versions and actor/payload-bound operation receipts govern qualification saves. The current roster and every service's qualification order are batched into the existing settings response; saves return the updated projection. Qualification writes validate active membership in one locking batch. Form changes stay local and the scoped settings cache invalidates booking choices after Save.

Routine-booking contracts carry optional `assignmentMode`: absent preserves legacy assigned-people behavior, `assigned` is explicit existing behavior, and `qualified_if_unassigned` opts into selection. Create/edit/publish/resume validate current service setup and full-workspace Job assignment permission for qualified mode. Current publisher assignment authority is rechecked for execution and queued outcome email too. The approved editor and workflow card are now connected through the existing settings/proposal/edit endpoints. Qualified and assigned submissions both preserve the explicit reviewed choice, including changing a previously qualified rule back to assigned people.

The shared booking engine loads the full bounded candidate pool, availability and busy visits once, resolves local clock windows in one batch, then compares candidate slots in memory. Shared busy visits deduplicate and union their people. Earliest start wins; saved preference order breaks equal starts. Current candidate user rows are share-locked through reservation so suspension/deletion cannot race a completed assignment. Existing Job/Work Order assignments retain the original team-intersection path. An empty shared crew gets a manual-assignment notice rather than an inferred crew.

The existing current workspace mutation lock encloses selection, canonical Job assignment/history, reloaded visit revisions, canonical scheduling, durable receipts and notice intents. Failed scheduling/receipt writes roll back the assignment and schedule together. Booking notifications snapshot the selected worker's name; the ordinary assignment notice is coalesced with the scheduled visit so the same operation does not announce both separately. Exact worker retries cannot choose another person or duplicate writes.

Qualification statement triggers wake only waiting qualified-mode occurrences for the affected service inside their original cutoff. Current member-state and availability/Calendar wakeups also account for qualified candidates of unassigned Jobs. No old Jobs are enrolled, no cutoff extends, and no booked assignments change when a qualification is removed. Existing outbox/BullMQ transport, no-slot suppression and lifecycle policies remain in place. No model calls are used for selection, retries or delivery. The Workflows assistant alone gains the explicit policy field; its guide explains configured qualifications and multi-person crew limits.
